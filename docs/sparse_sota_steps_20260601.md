## Implemented Changes

- Step1 large-pool sparse baseline:
  `eval_cambridge_hybrid.py` already supports
  `--landmark_candidate_source all_gaussians --max_landmarks 200000`.
- Step2 solver-weighted descriptor fusion:
  all-Gaussian pair caches can now be generated by
  `calibrate_landmark_matchability.py --landmark_candidate_source all_gaussians`;
  launcher support was added too.
- Step3 feedback pair scorer:
  verified existing listwise `train_scene_matcher.py` flow on all-Gaussian
  listwise caches.
- Step4 ambiguity-aware PnP ordering:
  added `ambiguity_aware` match filter mode. The first implementation was too
  aggressive and broke PROSAC by discarding the score prefix; it was corrected
  to preserve a 75% high-score prefix for large pools and use the remaining
  budget for local-geometry/patch/coverage diversity.
- Step5 detector target refinement:
  added `loc_gs.scripts.build_sparse_feedback_detector_targets` to build
  split-audited sparse feedback detector heatmaps from listwise all-Gaussian
  pair caches. Detector target rasterization was optimized from full-image
  Gaussian splatting to local-window splatting.

### Gate Decision

None of the current Step2/Step4 routes reaches the sparse SOTA target.

- Step2 is conservative and slightly improves R@10, P90, P95, and severe-rate,
  but macro median TE is marginally worse than Step1. It is not a main result.
- Step4 improves macro median TE by only 0.251 cm and P90 by 1.646 cm, but
  R@5 drops by 0.637 pp, P95 is not improved, and OldHospital gets a TE>5m
  failure. It is a diagnostic tradeoff, not a paper-facing sparse result.
- The very large inlier increase in Step4 confirms that the scorer/filter can
  find many PnP-consistent correspondences, but those correspondences do not
  translate into high-precision localization. The limiting issue is not simply
  match count or landmark availability; it is precision-aware ordering and
  false-consensus control.

Next method direction:

- Keep Step1 allgauss200k as the new sparse availability baseline while
  storage/runtime are ignored.
- Redesign Step4 around solver-quality ordering rather than inlier inflation:
  score correspondences by reprojection-tight consensus, 3D depth/span
  conditioning, local repeated-structure conflict, and per-query tail risk.
- Do not move this route to official Cambridge test until a train/full split
  improves macro median by at least 0.5 cm, improves R@10 or R@5 by at least
  0.5 pp, and does not regress P90/P95 or hard scenes.

## Step6 Bootstrap-Consensus Diagnostic

Motivation: Step4 produced many more PnP inliers but did not improve strict
high-precision recall. Step6 adds a query-observable sparse-only
`bootstrap_consensus` mode:

1. run one high-score OpenCV/PnP bootstrap pose,
2. score candidate correspondences by reprojection agreement with that pose,
3. pass the consensus score into PROSAC so the final sparse PnP prefix is
   ordered by tight pose consistency rather than only descriptor/scorer value.

This is still a single fixed sparse path and uses no test/GT pose information.

Implementation:

- `loc_gs.scripts.eval_cambridge_hybrid.bootstrap_consensus_match_filter`
- CLI: `--sparse_match_filter_mode bootstrap_consensus`
- Unit test:
  `tests/test_eval_cambridge_hybrid_cli.py::test_bootstrap_consensus_filter_demotes_high_score_reprojection_outlier`

Decision:

- Step6 is useful diagnostically: on OldHospital it improves median TE by
  1.278 cm over Step1 and 0.688 cm over Step4, with better R@10/R@5/R@2 and
  better P90/P95.

  redesign should use a protected native high-precision core and activate
  bootstrap consensus only when the native sparse pose is low-confidence, or
  should learn/query-estimate confidence before choosing the PnP ordering. That
  route must be treated carefully because per-query gating cannot use test
  outcomes or GT pose.

Interpretation:

- The oracle gap is large. Step4 oracle improves macro median TE from
  15.320 cm to 13.479 cm and R@10/5 from 0.445 to 0.484. Step6 oracle improves
  OldHospital/ShopFacade median from 9.231 cm to 7.481 cm and R@5/5 from 0.441
  to 0.478. The candidate routes contain useful sparse signal.
- A simple inlier-bin gate is insufficient. Query-observable sparse confidence
  features improve over inlier-only gating, but the current one-dimensional
  stump is still too weak to close the oracle gap.
- The reg50 guard fixes the most serious Step4 failure mode: held-out 50 cm
  regressions drop from 31 to 0 and mean delta becomes slightly positive for
  accuracy (`-0.098 cm`). It preserves small R@10/R@5/R@2 gains, but P90 no
  longer improves over baseline.
- The reg20=0 guard is too conservative. It removes most route activation and
  loses the median/R10 benefit. Reg20 should remain a reported risk metric, not
  the default hard rejection rule.
- Step6 remains a hard-query correction candidate, not a global path. Even with
  reg50 train guard, held-out eval folds still have a few large regressions.
- A depth-2 rule gate is more conservative than the stump and reduces Step4
  reg20 from 19 to 9 and Step6 reg20 from 9 to 7, but it does not materially
  improve median or tail metrics. The failure is not just missing one extra
  scalar threshold.

Current sparse-stage conclusion:

- Step1 allgauss200k remains the sparse availability baseline.
- Step2 solver-fused descriptors are conservative but not sufficient for SOTA.
- Step4/Step6 contain nontrivial correction signal, proven by oracle and
  confidence-gate diagnostics, but current query-observable gates are not strong
  enough for a main paper result.
- Next implementation should stop tightening shallow gates and instead improve
  the candidate ordering itself: the pair/listwise scorer needs explicit
  information-aware labels or losses for reprojection-tight consensus,
  2D/3D coverage, repeated-structure conflict, and high-precision pose
  conditioning. This must remain train-only for model selection and must not use
  official test outcomes.
